# 12-Minute Demo Runbook — Testing CAP against SAP HANA Cloud

Goal: show a fully green SQLite baseline, wire up HANA testing, then live-add two
HANA-only features (fuzzy search + a native `dayname()` view) — each red on SQLite,
green on real HANA. Part 5 is generated by an AI agent using the hana-testing skill.

> **Pre-flight (do this BEFORE you present — not on stage):**
>
> ```bash
> # 1. HANA instance already exists in CF (we do NOT create it live).
> cf target -o <org> -s <space-with-hana>     # e.g. the space that holds recap-test-hana-db
> cf services                                  # confirm recap-test-hana-db = "create succeeded"
>
> # 2. Binding already exists (.cdsrc-private.json). If missing, re-create:
> cds bind --to recap-test-hana-db --for test
>
> # 3. Deploy the model once so `npm test` is instant on stage:
> npm run deploy:test        # cds deploy --to hana:recap-test-hana-db --profile test --auto-undeploy
>
> # 4. Warm caches so the first `npm test` isn't slow:
> npm test
> ```
>

## 4 · Fuzzy search LIVE — 2.5 min

Add typo-tolerant search the CAP-idiomatic way: `$search` + `@Search.fuzzinessThreshold`.

**4a.** In [srv/worldcup-service.cds](srv/worldcup-service.cds), after the closing
`}` of the service, add:

```cds
annotate WorldCupService.Players with {
  @Search.fuzzinessThreshold: 0.7
  name;
};
```

**4b.** Create `test/FuzzySearch.test.ts`:

```ts
import cds from '@sap/cds';
const { GET, expect } = cds.test(__dirname + '/..');

describe('Fuzzy search — HANA only', () => {
  it('finds Mbappé despite the typo "Mbape"', async () => {
    const { data } = await GET`/odata/v4/worldcup/Players?$search=Mbape`;
    expect(data.value).to.containSubset([{ name: 'Kylian Mbappé' }]);
  });

  it('finds Gündoğan from "Gundogan"', async () => {
    const { data } = await GET`/odata/v4/worldcup/Players?$search=Gundogan`;
    expect(data.value).to.containSubset([{ name: 'İlkay Gündoğan' }]);
  });
});
```

**4c.** Prove the transition:

```bash
npm run test:sqlite -- test/FuzzySearch.test.ts   # ❌ empty — SQLite $search is LIKE substring
npm test -- test/FuzzySearch.test.ts              # ✅ HANA fuzzy match
```

**Line:** "Same standard OData `$search` — HANA makes it typo-tolerant; SQLite can't."

## 5 · Skill + AI-generated native `dayname()` view — 2.5 min

**5a.** Open the skill: [.agents/skills/hana-testing/SKILL.md](.agents/skills/hana-testing/SKILL.md).
One sentence: "Any agent that touches CAP DB code MUST add a HANA-backed test."

**5b.** Ask the AI agent (paste this prompt):

> Add a `PlayerProfiles` view to `WorldCupService` that returns each player's birth
> weekday using the HANA `dayname()` function, and follow the hana-testing skill.

**5c.** Expected agent edit in [srv/worldcup-service.cds](srv/worldcup-service.cds)
(the baseline `Players` projection is already `@cds.redirection.target`, so adding
this second projection of `worldcup.Players` compiles cleanly):

```cds
  @readonly
  entity PlayerProfiles as select from worldcup.Players {
    key ID,
        name,
        position,
        birthDate,
        dayname(birthDate) as bornOnWeekday : String   // HANA-only
  };
```

...and a HANA-backed `test/PlayerProfiles.test.ts` (HANA returns the weekday in
UPPERCASE — the agent verifies on HANA):

```ts
import cds from '@sap/cds';
const { GET, expect } = cds.test(__dirname + '/..');

describe('PlayerProfiles — HANA dayname() (HANA only)', () => {
  it('returns the birth weekday for each player', async () => {
    const { data } = await GET`/odata/v4/worldcup/PlayerProfiles`;
    // 1998-12-20 is a Sunday
    expect(data.value).to.containSubset([{ ID: 1, bornOnWeekday: 'SUNDAY' }]);
  });
});
```

**5d.** Deploy + run:

```bash
npm run deploy:test
npm test
```

**Close:** "The skill makes 'test it on HANA' the default — even when an AI writes
the code."
